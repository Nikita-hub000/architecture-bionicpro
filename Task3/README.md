## Что реализовано

### Компоненты решения
- **`reports-api`** — API отчётов. При запросе формирует/находит готовый отчёт и возвращает ссылку.
- **MinIO** — S3‑совместимое объектное хранилище для сохранения готовых отчётов (`bucket: reports`).
- **Nginx (CDN-эмуляция)** — reverse proxy перед MinIO с включённым кешированием ответов.
- **ClickHouse (OLAP)** — источник витрины `report_mart` + `etl_watermark` (используется только при генерации/промахе кеша).

---

### Алгоритм обработки запроса отчёта
1) Пользователь нажимает “Download Report” → UI идёт в **BFF** (`bionicpro-auth`), BFF проксирует запрос в `reports-api`.
2) `reports-api`:
- проверяет **готовность данных** через `etl_watermark` (не отдаёт “необработанный” период),
- вычисляет **ключ отчёта** в S3 по схеме (см. ниже),
- делает **проверку существования** объекта в S3 (`HEAD`):
    - **если объект есть** → возвращает **`cdnUrl`** на уже сохранённый отчёт (OLAP не трогается),
    - **если объекта нет** → читает отчёт из ClickHouse витрины (`report_mart`), сохраняет JSON в MinIO (S3 `PUT`), затем возвращает `cdnUrl`.
3) Клиент скачивает отчёт по `cdnUrl` через Nginx, который кеширует файл.

---

### Структура хранения в S3 (быстрый доступ + версия)
- Bucket: `reports`
- Key (версионированный, чтобы не делать purge CDN):
    - `<userKey>/<period_from>_<period_to>/<etl_loaded_at>.json`

Где:
- `userKey` берётся **из токена** (в учебной версии — `email`),
- `etl_loaded_at`/watermark обеспечивает **автоматическую инвалидацию**: после очередного ETL меняется ключ → меняется URL → CDN кешируется заново без очистки старого.

---

### CDN (Nginx) — что настроено
- Reverse proxy на MinIO: `proxy_pass http://minio:9000/reports/`
- Кеширование ответов по URL:
    - `proxy_cache` включён,
    - добавлен заголовок `X-Cache-Status: MISS/HIT` для проверки работы кеша.

---

### Обновление кеша (инвалидация)
Инвалидация реализована **через версионирование ключа**:
- новый ETL → новый `etl_loaded_at`/watermark → новый S3 key → новый URL → CDN кешируется как новый объект.
- старые отчёты остаются в S3 (можно чистить по lifecycle-политике позже, при необходимости).

---

### Что получаем по эффекту
- Повторные запросы одного и того же отчёта:
    - не ходят в ClickHouse,
    - обслуживаются через S3/CDN,
    - уменьшают нагрузку на OLAP и ускоряют отдачу отчётов пользователям.
